# Page Spec

本文件记录当前静态原型的页面事实源、交互要求和后续重构约束。当前阶段以页面完整、文字准确、点击层级准确为第一优先级。

## 实现原则

- 除明确需要改交互的页面外，页面正文直接使用 `extracted_screenshots/` 中的导出截图作为事实源，避免手工重写造成漏字、错字。
- 禁止使用 OCR、位图转 CSV、位图自动识别工具提取文案。后续真实 HTML 化时，只能人工视觉读图整理文字。
- `#/splash` 与 `#/driver/splash` 改为随机全屏开屏图池，旅客端和司机端图池不同；`#/station/home` 已迁移为真实 HTML 页面，改用新设计底座重建首页信息层级。
- `#/services` 已从截图热区页迁移为真实 HTML 目录页，保留左侧分类层级与右侧服务分组，旅客端与司机端入口直接跳转，其余条目先用原型反馈承接。
- `#/station/select` 和 `#/station/switch` 是自定义 HTML 页面，复用 `extracted_page04_station_icons/` 的 10 个站点图标，并使用生成的站点建筑图做横向滑动卡片。
- `#/feedback/submit`、`#/feedback/mine`、`#/profile`、`#/driver/profile` 已迁移为新底座长页；对应的 `-more` / `-bottom` 路由只负责滚动到下方锚点段。
- 司机端上层入口 `#/driver/splash` 点击后进入 `#/driver/short-haul/booking`，与首页第 8 个“短途复载”入口效果一致。
- `#/design-system` 是开发辅助页，用来检查全局 token、按钮、徽标、列表和表单组件是否足够统一。

这些选项已经做成可点击热区，并用蓝色描边表示当前选择。由于当前是截图保真原型，原截图中的默认选中态不会被删除，真实 HTML 重构时需要做成单一选中态。

| 页面 | 可选项 |
| --- | --- |
| `#/nav/route` | `B1`、`F1`、`F2`、`F3` |
| `#/announcements` | `全部`、`紧急`、`通知`、`提示`、`活动`；点击后会过滤公告列表；当前站点为北京南站时公告内容同步南站口径 |
| `#/feedback/submit` | `投诉`、`建议`、`咨询`、`表扬`；`站内设施`、`出租车`、`网约车`、`地铁`、`停车场`、`工作人员`、`安全问题`、`其他` |

## 截图覆盖

- 原始导出截图共 48 张。
- 当前路由直接使用 44 张截图。
- 未直接使用的截图文件有 6 张：`P02-02_全部服务页.png`、`P05-01_首页.png`、`P04-02_站区切换页.png`、`P05-02_站区切换页.png`、`P06-01_站区切换页.png`、`P06-02_站区切换页.png`。原因是 `#/services`、`#/station/home`、站点选择/切换已按用户要求改为自定义交互页。
- 当前路由数量仍保持 49 个，关键骨架页已经从截图热区壳转成自定义 HTML 长页，其余页面继续以截图事实源保真。

## 本轮验证记录

- 使用 Chrome headless/CDP 核查所有页面路由，截图页与新底座页都可正常打开，关键交互仍可点击。
- 自定义站点页核查通过：`#/station/select` 与 `#/station/switch` 均有 10 个站点按钮和 1 个确认按钮。
- 链接关系核查通过：47 个 `data-to` 目标均存在，没有死链。
- 站区切换核查通过：清空本地存储后默认北京西站，点击北京南站后当前选中变为北京南站，确认后进入 `#/station/home` 并写入 `arrive-beijing.station=south`。

## 后续真实 HTML 重构提醒

- 先按本文件和 `docs/page-map.md` 建组件，不要直接按视觉喜好删页面或删文案。
- 每个页面真实 HTML 化前，必须对照原截图人工视觉读图确认中文文字。
- 如果某个页面只是上一页滚动后的状态，也要保留为独立可达状态，不能合并到无法到达的滚动区域里。
